# Маршрутизация

| Задача | Первый инструмент | Эскалация / исправление выбора | Критерий остановки |
|---|---|---|---|
| Структурировать запрос | LLM + `templates/brief.md` | человек при выборе метрики/границы | решение, владелец, метрика и срок записаны |
| Проверить таблицу | `pulse.py analyze` с ключом, единицей, периодом и диапазоном | исправить схему; не интерпретировать агрегаты как пользователей | пропуски, дубли и единица наблюдения записаны |
| Оценить экономику | `pulse.py economics` на явных допущениях | владелец/финансы для фактических N, M, C, S и горизонта | формулы, чувствительность и статус входов воспроизводимы |
| Оценить вклад удержания и новых номеров | `pulse.py paid-months` на JSON-сценариях | финансы для фактического оттока и расходов | вклад, граница цели и предельные вложения воспроизводимы |
| Спланировать объём пилота | `pulse.py sample-size`, навык `skills/pilot-design` | аналитик для базовой доли, кластеров и повторных событий | объём, нужный поток в неделю и ограничения записаны |
| Найти гипотезы о поведении | навык `skills/model-interview`, дешёвая модель, три независимых прогона | реальные интервью для проверки | гипотезы с альтернативами и способом проверки; ничего не выдано за спрос |
| Проверить черновик решения | навык `skills/redteam-options`, модель среднего уровня без истории чата | человек при споре о принятии замечания | у каждого замечания есть решение и запись до/после |
| Найти открытые факты | доступный браузер, первичный сайт | отчёт/PDF и ручная проверка; сниппет не доказательство | URL, дата, точная выдержка и ограничение в ledger |
| Разобрать интерфейс | DOM + screenshot с viewport и состоянием | повторить failed capture один раз; сохранить только успешный материал | видимые наблюдения отделены от гипотез поведения |
| Найти причины поведения | реальные согласованные интервью/UX-тест | модельные респонденты только для гипотез | есть реальный способ проверки, нет подмены спроса |
| Сравнить решения | LLM по workflow | человек для существенного/необратимого выбора | A/B/C, возражения, обратимость и условия выбора |
| Пересмотреть решение | diff новых материалов + ledger + `status` | человек при срабатывании триггера | до/после и state/decision/ledger/updates согласованы |
| Проверить артефакты | `pulse.py validate` | исправить источник/ID/state, затем повторить | проверка проходит без скрытия ошибок |

Дорогую модель включай только для синтеза конфликтующих материалов или сложного выбора. Схему, дубли, ссылки, даты и арифметику сначала проверяй локально. Если инструмент недоступен, запиши сбой и не утверждай, что операция выполнена.

Выбор конкретной модели и фактическая экономия маршрутизации должны подтверждаться журналом: задача, модель/инструмент, причина, стоимость, ошибка и смена маршрута. Статическая таблица сама по себе не является измеренной model routing-системой.
