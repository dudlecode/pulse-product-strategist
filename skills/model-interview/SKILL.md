# Модельное интервью

Цель — гипотезы и вопросы для реальных интервью. Результат никогда не доказывает спрос, распространённость или готовность платить. Методика — `knowledge/interviews.md`.

## Шаги

1. Опиши три разных вымышленных профиля из сегментов кейса. Укажи, чего респондент не знает. Никаких данных реальных людей.
2. Для каждого профиля составь пять вопросов о последнем конкретном случае: что произошло, как узнали, что делали сами, что было хуже всего, когда помощь ещё была бы вовремя. Формулировки между профилями разные. Решение не подсказывай.
3. Запусти каждый профиль отдельным вызовом, чтобы ответы не влияли друг на друга. Если среда умеет субагентов — три субагента параллельно на дешёвой модели. Если нет — три отдельных чата или три последовательных запроса с чистым контекстом.
4. Сохрани в `interviews/` по файлу на прогон: дата, модель, расход, полный prompt, полный ответ без правок, замечание о качестве. В начале файла — пометка «синтетический респондент».
5. В `interviews/synthesis.md` запиши только повторившиеся гипотезы. Для каждой — альтернативное объяснение и способ проверки на реальных людях или данных. Единичные наблюдения — отдельным списком.
6. Добавь гипотезы в `ledger.md` с типом «гипотеза» и ограничением «синтетические ответы».

## Чего нельзя

- Писать «клиенты хотят X» на основании модельного ответа.
- Использовать суммы, сроки и частоты из ответов как данные.
- Править ответ, чтобы убрать нестыковки: они показывают надёжность источника.

## Критерий готовности

Есть три файла прогонов, синтез с проверкой для каждой гипотезы и обязательство провести реальные интервью в `state.json`.
